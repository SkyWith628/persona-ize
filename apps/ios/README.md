# Persona_ize for iPhone

iOS 16 이상용 SwiftUI 앱과 보조 키보드 확장이다. 앱은 탭 네 개로 나뉜다. 작성 탭에서 상대를 골라 합성 초안을 첨삭하고, 상대 탭에서 상대 등록·페르소나 편집·합성 대화 가져오기를 하며, 이력 탭에서 최근 첨삭을 다시 보고, 계정 탭에서 사용량 확인·비밀번호 변경·로그아웃·계정 삭제를 한다. 추천을 검토한 뒤 ‘키보드에 준비’를 누르면 확장이 읽을 문장 한 개를 앱 그룹에 저장한다. 메신저에서 지구본으로 키보드를 전환하고 ‘준비한 문장 넣기’를 누르면 현재 커서에 삽입한다. 키보드 설정에서 ‘전체 접근 허용’을 켜면 앱을 거치지 않고 키보드 맨 윗줄의 ‘○○에게 맞게’로 입력창의 초안을 바로 다듬어 바꿔 넣는다(버튼을 누를 때만 입력창을 읽고, 전송은 하지 않는다). 이때 키보드는 앱이 앱 그룹에 둔 로그인 토큰을 쓰므로 앱에서 먼저 로그인해야 한다. 켜지 않으면 준비한 문장 넣기만 된다. 계정 탭의 ‘준비한 문장 지우기’로 저장본을 삭제한다. 비밀번호는 저장하지 않는다. 로그인은 `POST /v1/auth/token`으로 받은 Bearer 토큰(서버 기본 14일, 연장 없음)이고, 앱은 이 토큰을 키체인(이 기기에서만, 잠금이 풀린 동안)에 두어 다음 실행 때 다시 로그인하지 않는다. 쿠키와 CSRF 헤더는 쓰지 않는다. 로그아웃·계정 삭제·토큰 만료(401 `invalid_token`) 때 키체인과 앱 그룹의 토큰을 지운다. 가입은 `register` 뒤 토큰 발급 두 단계다(가입 응답에는 토큰이 없다). 키보드 확장은 키체인을 읽지 않고 앱 그룹 파일(`keyboard-link.json`, 잠금 중 읽기 불가)의 토큰을 쓴다 — 키체인 접근 그룹(entitlements)은 더하지 않았다. 첨삭 조건은 기본이 `auto`(서버가 고른다, 웹과 같다)다.

단위 테스트는 `xcodebuild -project PersonaIze.xcodeproj -scheme PersonaIze -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test`로 돌린다. 명령줄에서 실기기로 빌드할 때는 `DEVELOPMENT_TEAM=<팀 ID> -allowProvisioningUpdates`를 붙인다. App Group은 Xcode의 Signing & Capabilities에서 Team을 한 번 선택해야 등록된다.

## 화면 흐름 검사 (시뮬레이터, 맥)

`scripts/ios_ui_check.sh [시뮬레이터 이름·UDID]`가 XCUITest(`UITests/FlowUITests.swift`, 스킴 `PersonaIzeUITests`)를 돌린다: 예시 화면 건너뛰기 → 가입 → 첫 상대 만들기 → 초안 다듬기 → 이력 → 완전히 끄고 다시 열기(로그인 유지) → 로그아웃 → 다시 열기(로그인 화면). 두 번째 검사(`testImportPastedKakaoWithSpeakerGuide`)는 새로 가입한 뒤 상대 화면에서 대화방을 추가하고, 카카오톡 방법으로 지어낸 대화(안드로이드 꼴, 제목 줄 없음)를 '가져올 대화' 칸에 넣어 가져온다 → 내 이름을 비워 둬 뜨는 화자 안내("누가 나인지 알 수 없어요" + 파일의 이름)를 확인 → 내 이름을 넣고 다시 가져와 '말투 분석 완료'와 건수(내가 쓴 것 2개)를 본다. 세 번째 검사(`testExpiredTokenReturnsToSignInWithNotice`)는 토큰 만료 안내를 두 경로로 본다: 가입 뒤 앱을 끄고 토큰을 폐기 → 다시 열면 로그인 화면과 "로그인이 만료됐어요. 다시 로그인해 주세요." → 다시 로그인 → 쓰는 중 폐기 → 이력 탭의 요청이 401 `invalid_token` → 같은 안내 → 다시 열어도 로그인 화면. 폐기는 서버의 실제 기능이다: 검사 실행기가 같은 계정으로 `POST /v1/auth/token`을 받아 `POST /v1/auth/logout-all`(그 토큰만 남기고 다른 세션·토큰 전부 폐기, Bearer라 CSRF 불필요)을 부른다. 실행기도 시뮬레이터 안에서 돌아 스크립트가 등록한 루트 인증서로 localhost HTTPS를 믿는다. 스크립트가 임시 인증서를 만들어 시뮬레이터에 등록하고, 가짜 모델·메모리 저장소 서버를 `https://localhost:8443`에 띄웠다가 내린다(Docker·DB·모델 키 불필요, 계정은 실행마다 새로 만든다).

- 기본 스킴(`PersonaIze`)의 `test`에는 들어 있지 않다 — 서버가 있어야 돌기 때문이다. CI는 이 검사를 돌리지 않는다.
- 검사는 `-server <주소>` 실행 인자로 로그인 화면의 서버 주소를 덮어쓰고, 로컬 주소가 아니면 시작하지 않는다. 빌드에 든 기본 서버(운영)로는 요청이 가지 않는다. `-uiTestReset`(디버그 빌드 전용)은 앱 설정을 지워 처음 상태에서 시작하게 한다.
- 서명을 끄고(`CODE_SIGNING_ALLOWED=NO`) 빌드하면 키체인 저장이 조용히 실패해 '다시 열기' 단계가 깨진다. 단위 테스트는 꺼도 되지만 이 검사는 켠 채로 돌린다.
- 보지 않는 것: 키보드 확장(앱 그룹 읽기·메모 앱에 넣기), 대화 파일 첨부(fileImporter)와 서버가 따르지 않은 화자 지정 안내, 실제 모델의 원문 유지 응답 — 아래 실기기 순서로 확인한다.
- 램 8GB 맥에서는 시뮬레이터 첫 부팅 뒤 몇 분 동안 부하가 커서 검사 실행기가 멈춰 죽는다(11/27). 부하가 가라앉은 뒤 다시 돌린다.

## 실기기 설치

1. iOS SDK가 설치된 Xcode에서 PersonaIze.xcodeproj를 연다. 이미 생성된 프로젝트를 사용하면 XcodeGen 설치는 필요 없다.
2. 프로젝트 Build Settings에서 PERSONA_BUNDLE_ID를 본인 팀의 고유 식별자로 지정한다. 기본값은 com.skywith628.personaize다. 키보드 식별자는 이 값에 .keyboard를 붙인다.
3. 두 타깃의 Signing & Capabilities에서 같은 Team을 선택하고 자동 서명을 켠다. Apple Developer 계정에 두 App ID와 group.<앱 번들 ID>를 등록하고 양쪽에 같은 App Group을 연결한다. 양쪽 서명 프로파일에 해당 그룹이 포함되어야 한다.
4. PersonaIze 스킴과 연결된 아이폰을 선택해 Run한다. 로그인 화면에 기기에서 접근 가능한 신뢰된 HTTPS 백엔드 주소를 입력한다. 백엔드에는 시연 계정과 합성 데이터로 만든 상대와 저장된 페르소나가 있어야 한다. 로그인 상태는 앱을 종료해도 남는다(키체인의 토큰). 확인할 것: 앱을 완전히 끈 뒤 다시 열면 로그인 화면 없이 들어가는지, 로그아웃 뒤 다시 열면 로그인 화면인지, 다른 기기(웹)에서 비밀번호를 바꿔 토큰이 폐기되면 다음 요청에서 "로그인이 만료됐어요"와 함께 로그인 화면으로 돌아가는지, 앱을 지우고 다시 설치하면 로그인 화면부터인지, 새 계정 가입 직후 바로 들어가는지(승인제 서버는 안내만), 예전 빌드(쿠키 로그인)에서 올린 기기는 다시 로그인하면 키보드 첨삭이 되는지.
5. 설정 → 일반 → 키보드 → 키보드 → 새로운 키보드 추가에서 Persona_ize를 선택한다. 메모 앱에서 추천 문장 삽입과 원래 키보드로 전환을 확인한다. 원문 유지 응답, 네트워크 오류 후 같은 초안 재시도, 준비 문장 삭제도 확인한다. 키보드 안 첨삭(전체 접근)이 토큰으로 되는지, 앱에서 로그아웃한 뒤에는 키보드가 다시 로그인을 안내하는지도 본다. 같은 카카오톡 파일을 화자를 바꿔 다시 올리면 분석 구역에 "화자는 바뀌지 않았어요" 안내가 뜨는지 본다(고치는 화면은 PC 웹에만 있다).

## TestFlight

배포에 사용할 Xcode와 Apple Developer Program 팀에서 App Store Connect 앱 레코드를 같은 Bundle ID로 생성한다. 프로젝트 버전과 빌드 번호를 정하고 PersonaIze 스킴의 기기 대상을 Any iOS Device로 선택한다. Product → Archive 후 Organizer에서 Validate App과 Distribute App → App Store Connect를 진행한다. 처리 완료 후 TestFlight에서 테스트 그룹에 빌드를 배정한다.

프로젝트 설정 원본은 project.yml이다. 타깃 구성을 바꾸면 이 디렉터리에서 xcodegen generate로 프로젝트를 다시 생성한다. Xcode에서 직접 설정한 팀이나 식별자를 유지하려면 재생성 전에 project.yml에 반영한다.
