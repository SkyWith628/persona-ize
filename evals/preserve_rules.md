# 보존 항목 분류표 v0

작성: 평가·품질 담당 (초안은 팀장, 2026-11-08). 사용자·시나리오 담당이 현실성을 검토한다.
코드: [`backend/app/ai/preserve.py`](../backend/app/ai/preserve.py) · [`validation.py`](../backend/app/ai/validation.py). 이 문서를 바꾸면 PR에 "코드 반영 필요"를 적는다.

원칙: **누락이 오탐보다 위험하다.** 애매하면 보존 항목에 넣는다. 사실 보존 실패는 스타일 점수로 상쇄하지 않는다.

## 분류

| kind | 설명 | 예 | 검증 방법 | 결과에서 허용되는 변형 |
|---|---|---|---|---|
| datetime | 날짜·요일·시각·상대 시간 | 내일 오전, 11월 5일, 다음 주 수요일, 3시 | 원문 집합 ⊆ 결과 집합 (공백 제거 비교). 결과에만 있으면 `fact_added` | 없음. "내일 오전"→"내일 아침"도 현재는 실패(검토 필요) |
| quantity | 수량·금액·횟수·비율 | 3부, 2명, 50만 원, 10% | 같음 | 없음 |
| person | 이름이 드러난 사람 | 박지현, 지현 팀장님, 서연 파트장님, 서연 선배 | 같음. 설정된 호칭(address_term)은 추가 허용 | 이름 없는 직함("팀장님", "파트장님", "매니저님") 추가·삭제는 자유. 친족 호칭("형")은 아래 '호칭' 참고 |
| possibility | 가능/불가 방향 | 어렵습니다, 못 돌립니다, 가능합니다 | 원문이 불가면 결과에도 불가/부정이 있어야 함. 원문에 없던 불가가 생기면 실패 | 표현은 자유("어렵습니다"→"힘들 것 같습니다") |
| promise | 약속·의지 | 보내드릴게요, 맡겠습니다 | 원문에 있으면 결과에 어떤 형태로든 있어야 함 | 종결형 변경 자유 |
| condition | 조건 | 수요일로 조정해 주시면, 가능하다면 | (현재 추출만, 검증 미적용) | — |
| negation | 일반 부정 | 안, 못, 않, 없 | possibility와 함께 방향 판단 | — |

## 직함과 이름 (2026-11-16, 규칙 버전 `rules-2026-11-16b`)

직함 사전은 [`backend/app/domain/titles.py`](../backend/app/domain/titles.py)의 `ORG_TITLES` 하나다(말투 프로필과 같이 쓴다). 사전을 고치면 `VALIDATOR_VERSION`을 올리고 기준 조건을 다시 돌린다 — 결과의 `validator_version`이 다른 실행끼리는 사실 보존 수치를 섞어 비교하지 않는다.

| 글 | person 항목 | 2026-11-16 이전 |
|---|---|---|
| 파트장님, 센터장님, 매니저님, 본부장님, 박사님 | 없음 (직함) | '파트장', '센터장', '매니저', '본', '박사'라는 사람 |
| 팀장님, 부장님, 선배님 | 없음 (직함) | 같음 |
| 지현 팀장님 | 지현 | 같음 |
| 서연 파트장님, 서연 책임님 | 서연 | '파트장', '책임' (이름은 놓쳤다) |
| 김팀장님 | 김 | 같음 |
| 김파트장님, 김수석님, 김선생님, 지현선배님 | 김, 김, 김, 지현 | '김파트장', '김수석', '김선생', '지현선배' |
| 부사장님 / 서연 부사장님 | 없음 / 서연 | '부' / '부' |
| 서연 파트장이, 제가 책임지고, 거절 의사를 | 없음 | 같음 |
| 어제 파트장님, 우리 매니저님, 회의록은 센터장님께 | 없음 (앞 낱말이 이름이 아니다) | '파트장', '매니저', '센터장' |
| 어제 팀장님, 우리 팀장님, 자료는 부장님께 | 없음 (`16b`부터) | '어제', '우리', '자료는'이라는 사람 |

- 이름 자리에 잡힌 낱말이 직함이면 사람이 아니다. 직함으로 끝나면 직함을 떼고 남은 것이 이름이다(긴 직함부터).
- 이름 뒤 직함: 예전 목록(팀장·부장·과장·대리·교수·대표·이사·사장·실장·주임, 선배, 선생님)은 예전 그대로다. 사전에서 새로 온 직함은 **'님'이 붙었을 때만** 이름 뒤 직함으로 본다 — '책임', '의사', '선임'처럼 보통 명사로도 쓰이는 말이 많다.
- 띄어 쓴 직함 앞의 낱말은 이름일 수 있을 때만 사람이다(`rules-2026-11-16b`). 날짜·대명사·꾸미는 말 목록(`_NOT_NAMES`: 어제, 오늘, 우리, 저희, 담당, 오신, 옆팀 …)에 있거나 조사로 끝나면('자료는', '회의에', 네 글자 '회의록은') 이름이 아니다 — 이름 없는 직함으로 본다. `16`에서는 새 직함 약 28개에도 이 오탐이 생겨 "어제 파트장님이 …"을 "파트장님께서 어제 …"로 바꾼 결과가 `preserve_missing`으로 실패했다. '지은'·'정이'처럼 조사 글자로 끝나는 이름은 그대로 사람이다(두세 글자는 '는/를/에/께'로 끝날 때만 조사로 본다). 목록에 없는 보통 명사('신규 매니저님'의 '신규')는 여전히 사람으로 잡힌다.
- 바뀐 결과: 원문에 없는 '파트장님'을 결과가 붙여도 `fact_added`가 아니다('팀장님'과 같아졌다). 이름이 붙은 '서연 파트장님'은 설정된 호칭이 아니면 여전히 `fact_added`다.
- 합성 대화·평가 원문에서 달라진 것은 1건이다: `c3:m08` "서연 파트장님, 오늘 스탠드업 회의록 공유드립니다." — '파트장' → '서연'. `eval_cases.csv` 원문 5건은 그대로다.

## 호칭

| 무엇 | 어디서 | 결과 |
|---|---|---|
| 원문·설정에 없는 친족 호칭(형, 누나, 오빠, 언니…)이 부르는 자리에 생김 | `validate_output` | `fact_added` (실패) |
| 원문·설정에 없는 직함·호격(파트장님, 서연 씨, 서연아…)이 생김 | `validation.address_leaks`, 워크플로 `register_warnings` | 경고만. 검증 결과와 재생성에 관여하지 않는다. 기본은 꺼짐 |
| 결과의 반말/존댓말이 설정의 격식과 다름 | 워크플로 `register_post_check` | 재생성 1회(기회는 그대로 두 번). 2차를 쓸 수 없으면 1차를 경고와 함께 추천. 합쇼체/해요체는 가르지 않는다. 기본은 꺼짐 |

누출은 알맹이(직함·이름·친족 호칭)로 견준다: 원문의 '파트장이'가 결과에서 '파트장님께서'가 된 것, '서연아'가 '서연 씨'가 된 것은 누출이 아니다. 이름을 부른 것('서연아')은 상대 별칭을 알 때만 찾는다.

## 검증 순서 (하나라도 실패하면 재생성 1회 → 재실패 시 원문 유지)
1. 보존 항목 누락 (`preserve_missing`)
2. 원문에 없는 사실 추가 (`fact_added`)
3. 가능/불가 방향 변화 (`negation_changed`)
4. 상대별 금지 표현 (`forbidden_phrase`)
5. 근거 id가 실제 검색 결과인지 (`evidence_unknown`)
