# 분산 측정 — 5사례 × A/B/C/D × 3회, Claude 실제 호출 (2026-11-09 새벽)

`run_eval.py --provider anthropic --conditions A,B,C,D --repeat 3`, Opus 5.5 `effort=medium`, 프롬프트 `rewrite-v1`, D 검색기 v2(재정렬). 요약 CSV: [eval-week3-abcd-repeat3.csv](eval-week3-abcd-repeat3.csv). 블라인드 시트: `evals/blind/week3-repeat3-sheet.csv`(36줄, 조건 숨김).
목적: 사례 20개가 오기 전에 **같은 입력이 얼마나 흔들리는지** 알아 루브릭 척도와 반복 횟수를 정한다.

## 조건별 (15회씩)
| | A | B | C | D |
|---|---|---|---|---|
| recommended / fallback | 15 / 0 | 15 / 0 | 15 / 0 | 15 / 0 |
| 모델 호출 수 (재생성 포함) | 15 | 18 | 18 | 18 |
| 지연 중앙값 / 최대 | 4.2초 / 5.9초 | 3.9초 / 7.5초 | 4.4초 / 15.9초 | 4.6초 / 17.1초 |
| 입력 / 출력 토큰 (15회 합) | 3,672 / 4,971 | 5,470 / 4,737 | 9,872 / 7,750 | 12,602 / 8,500 |
| 사례당 서로 다른 출력 수 (E001~E005) | 3·1·3·1·1 | 1·3·3·1·2 | 3·1·3·2·1 | 1·1·3·3·1 |

60회 전부 추천 성공, 원문 유지 0건. 재생성 9건은 **전부 E004(동기·사과)** 에서 B·C·D 각 3회 — 1차 출력이 매번 호칭('서연 씨'·'파트장님'·'서연님')을 넣고 검증에 걸렸다. 무작위가 아니라 **체계적**이다.

## 흔들림의 성격
- **안정적인 것**: 날짜·가능/불가·약속은 60회 모두 보존(검증 통과). E002 C·D는 3회 모두 글자까지 같다("지현 팀장님, 죄송하지만 이번 주 금요일은 어렵고, 다음 주 수요일까지는 가능합니다."). E001 D, E005 C·D도 동일.
- **흔들리는 것**: 덧붙이는 한 토막. E001 A는 "죄송합니다" 문장이 붙었다 안 붙었다, E003는 네 조건 모두 3회가 다 다르다("괜찮으면 알려줘!"/"어려우면 편하게 말해줘!"/"잠깐 쓰고 바로 돌려줄게"/"부탁 좀 하자ㅋㅋ"). 즉 **보존 항목은 고정, 어조 장식은 매번 달라진다** → 루브릭은 장식의 적절성을 보되, 1회 채점으로 조건을 가르지 말고 **3회 중 중앙값**으로 본다.
- **E003 D가 '형'을 붙였다**(r2·r3 "형, 토요일 오전에 차 좀 빌려줄 수 있어?"). 동생에게 '형'은 방향이 틀렸다. 원인은 그래프 사실 "형 또 그랬냐고 묻는 관계"(준호가 민수를 형이라 부른 것을 추출기가 관계 사실로 적음) — 모델이 이를 호칭 힌트로 오해했다. 검증은 '형'을 사람 추가로 잡지 못했다(사람 규칙이 이름·직함 위주). → ① 검증 규칙 추가(이번 커밋): 원문에 없던 친족 호칭(형·누나·오빠·언니·엄마·아빠)은 **설정된 호칭과 같을 때만** 허용, 아니면 `fact_added` → 재생성 ② 관계 사실 문장("형 또 그랬냐고 묻는 관계")의 품질은 추출 지시문 과제(그래프 담당 점검 항목).
- **E005 D recall이 0.5로 떨어졌다**(1·2차 실측은 1.0). 재정렬 v2의 상대 임계를 **가중 점수**로 잘라서 중요도가 낮게 적힌 '밥 약속' 사실이 관련성과 무관하게 빠졌다. 임계를 가중 전 점수로 바꾸고 최소 2건을 남기도록 고쳐 recall 1.0을 복구(fake 재확인). 실측 CSV의 D recall 0.5는 고치기 전 값이다.

## 비용·지연
- 60회 + 재생성 9회 = 69회 호출. 입력 31.6k + 출력 26.0k 토큰(캐시 읽기 제외). 조건당 15회 기준 D 입력은 C의 1.28배(이번엔 E003·E004 맥락이 길었다).
- 재생성이 있으면 15~17초. 요청 예산 20초 안이지만 여유가 작다. E004처럼 **매번 같은 이유로 재생성되는 사례는 프롬프트로 막는 게 맞다**("원문에 호칭이 없으면 넣지 않는다") → `rewrite-v2` 후보.

## 결정 제안
1. 사례 20개 실측은 `--repeat 3`으로 하고 블라인드 채점은 3회 중 1회(무작위)만 사람이 본다 — 비용 1/3, 분산은 이 메모의 숫자로 설명.
2. 루브릭 "자연스러움"에 **덧붙인 토막의 적절성**을 넣는다(E003 '잠깐 쓰고 돌려줄게'는 사실 추가인가 장식인가 — 평가 담당 판단).
3. `rewrite-v2` 프롬프트: 호칭 규칙 명시. 바꾸면 같은 5사례로 재생성률을 비교한다.

## 비용
Console 확인 전. 이 실행은 Opus 69회(입력 ~31.6k + 출력 ~26k + 캐시 읽기 ~85k).

# 후속 — rewrite-v2 (호칭 규칙 명시) 비교, 같은 날 새벽

`--prompt rewrite-v2 --conditions B,C,D --repeat 2` (Opus 30회): **재생성 0/30** (v1은 9/45). 60회 전부 추천.
v2 규칙: "설정에 호칭이 있으면 그것만, 없으면 새 호칭(이름·직함·형/누나…)을 넣지 않는다. 예시·맥락의 호칭을 베끼지 않는다. 제안은 warnings에." 모델이 규칙을 그대로 따라 E004는 1차에 통과하고 warnings에 "'서연 파트장님' 호칭을 쓰신 기록이 있다"를 적었다.
**부작용**: 친구(E005)·동생(E003)에서 '유진아'·'준호야'가 사라졌다 — 평가 페르소나가 격식 4 이상에만 호칭을 넣고 있었기 때문. 호칭 공급 규칙을 바꿔(상사·지인·친구·가족·연인에 characters.csv 호칭, 동료는 비움) 다시 돌리니 "준호야, 토요일 오전에…", "유진아 다음 달…"로 돌아왔고 재생성 0, E005 D recall 1.0.
**결정**: 기본 프롬프트를 `rewrite-v2`로 올린다. 호칭은 설정이 공급하고 모델은 만들지 않는다 — "명시 설정이 이긴다"(design.md ①)의 구현. 사례 20개 실측도 v2로.
