# D 조건 지연 분석 (2026-11-25, 모델 호출 없음)

`evals/summarize.py`로 11/24 dev 16사례 결과를 집계하니 **D의 지연 p95가 11.5초**(목표 8초)였다. 원인을 결과 CSV만으로 좁혔다. 새로 돌린 것은 없다.

- 자료: `eval-20261124-dev16-abcd-repeat3.csv`(192회, `rules-2026-11-24.2`), `eval-20261124-dev16-recheck-E011-E014-E020.csv`(36회, `rules-2026-11-24.3`)
- 모델 `claude-opus-5-5`, effort `medium`, 프롬프트 `rewrite-v3`. 지연은 `latency_ms`(요청 한 건 전체)다.

## 결론

1. **11.5초는 재생성 세 번이 만든 값이다.** D에서 8초를 크게 넘긴 세 실행(12.5 / 13.1 / 13.2초)은 모두 E020이고 모두 시도 2회였다. 그 재생성은 규칙의 구멍 때문이었고 `rules-2026-11-24.3`에서 고쳤다(decisions 11-24).
2. **고친 규칙의 재확인 결과로 바꿔 넣으면 D의 p95는 8.1초다.** 재생성 0건, 원문 유지 0건. 목표 8초에 0.1초 모자란다.
3. **지연은 거의 전부 출력 토큰 수다.** 시도 1회인 실행에서 지연과 출력 토큰의 상관은 C 0.91, D 0.95이고 입력 토큰과는 상관이 없다(C −0.04, D 0.07). 어림식은 `지연 ≈ 0.7초 + 출력 100토큰당 1.06초`.
4. **D가 더 느린 것은 그래프 검색이 아니라 모델이 더 많이 쓰기 때문이다.** 같은 사례·회차에서 D−C의 중앙값은 지연 +1.2초, 출력 토큰 +93. 출력 길이를 빼고 남는 차이(검색·그래프 조회 몫으로 볼 수 있는 것)는 0.2초쯤이다.
5. **늘어난 출력은 다듬은 문장이 아니다.** 결과 문장 길이의 중앙값은 네 조건 모두 58자 안팎인데 출력 토큰의 중앙값은 A 231 → B 229 → C 306 → D 403이다. 문장 밖의 출력(바꾼 이유·근거 같은 구조화 출력의 나머지 칸과, 출력 토큰으로 집계되는 그 밖의 것)이 맥락이 붙을수록 길어진다. CSV로는 그 안을 더 나눌 수 없다.

## 무엇을 해 볼 수 있나 (실제 모델 호출이 필요하다 — 아직 하지 않았다)

D를 8초 안으로 넣으려면 출력을 줄여야 한다. 입력(맥락 블록)을 줄이는 것은 지연에 거의 영향이 없다.

| 해 볼 것 | 기대 | 따져 볼 것 |
|---|---|---|
| 문장 밖 출력을 짧게: 프롬프트·출력 형식에서 바꾼 이유·근거 칸의 개수와 길이를 제한 (새 프롬프트 버전) | 출력 100토큰에 1초쯤 | 화면이 보여 주는 "바꾼 이유"·주의 문구가 줄어든다. 사실 보존·recall은 그대로인지 |
| `LLM_EFFORT`를 `low`로 | 출력 토큰이 줄 수 있다 | 사실 보존 통과율, 재생성 횟수. 재생성이 늘면 오히려 느려진다 |
| 재생성을 줄이기 | 재생성 한 번이 지연을 두 배로 만든다 | 규칙의 오탐을 줄이는 쪽(이미 한 번 효과를 봤다) |

측정은 `evals/summarize.py`의 지연 p95와 출력 토큰으로 한다. dev 16사례 × D × 3회면 48회다.
