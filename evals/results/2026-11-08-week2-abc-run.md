# 2주차 실측 메모 — A/B/C 비교, Claude 실제 호출 (2026-11-08 밤)

`run_eval.py --provider anthropic --conditions A,B,C`, 사례 5개(E001~E005), `--repeat 1`, Opus 5.5 `LLM_EFFORT=medium`, 프롬프트 `rewrite-v1`.
C 검색기 `knn-style-v1/st:intfloat/multilingual-e5-small:384:v1`, 과거 대화는 `data/synthetic/sample_conversations.json` 36건(묶음 18개)을 `user=eval`로 적재.
요약 CSV: [eval-week2-abc-anthropic.csv](eval-week2-abc-anthropic.csv). 같은 설정의 fake 모델 실행(검색만 확인): [eval-week2-abc-fake.csv](eval-week2-abc-fake.csv).

## 조건별 집계 (5사례씩)
| | A 페르소나 없음 | B 페르소나 | C B + 문체 예시 kNN |
|---|---|---|---|
| recommended / fallback | 5 / 0 | 5 / 0 | 5 / 0 |
| 모델 호출 수 (재생성 포함) | 5 | 6 | 6 |
| 지연 중앙값 / 최대 | 3.8초 / 5.2초 | 4.0초 / 10.3초 | 4.9초 / 14.5초 |
| 입력 / 출력 토큰 (캐시 읽기 제외) | 1,224 / 1,395 | 1,818 / 1,522 | 3,291 / 2,664 |
| 검색 recall (relevant_msg_ids 있는 3사례) | - | - | E002 1.00, E004 1.00, E005 0.50 |

17회 호출 합계: 입력 6,333 + 출력 5,581 + 캐시 읽기 20,768 + 캐시 생성 1,298 토큰. 시스템 프롬프트 캐시는 첫 호출에 만들고 나머지 16회 전부 읽었다.
C는 문체 예시 3~4개가 들어가 입력이 B의 1.8배, 출력도 길어졌다(설명·warnings가 늘어남). 사례당 1.2~1.5초 더 걸린다.

## C에서 문체 예시가 실제로 쓰였나
- **E002**: 검색 1·2위가 바로 그 장면(c1:m02~m05, "솔직히 이번 주 금요일은 어렵고…", "죄송하지만 수요일로 조정 부탁드립니다"). 모델이 둘을 `evidence_ids`로 들고 "과거에 쓰신 '죄송하지만'을 넣었다"고 이유를 적었다. B는 "금요일**까지는**"으로 뜻을 바꿀 뻔했는데(모델도 warnings에 자인) C는 원문 구조를 그대로 두었다. **C가 B보다 나은 가장 분명한 사례.**
- **E001**: B는 원문에 없는 사과 문장을 넣었고 C는 넣지 않았다. C의 warnings: "원문에 사과나 지연 사유가 없어 새로 넣지 않았습니다". 대신 보존 항목 '보내드릴게요'를 '보내드리겠습니다'로 바꿨다(검증은 통과 — 어미 변화는 보존 규칙상 허용). 격식 5 설정에는 맞지만 "보존 항목을 건드렸다"고 모델이 스스로 경고했다.
- **E003**: 예시의 'ㅋㅋ'가 전이돼 "부탁 좀 하자ㅋㅋ"가 붙었다. 동생 말투로는 자연스럽지만 **원문에 없는 문장 추가**다. 평가 담당이 `expected_notes`로 허용 여부를 정해야 한다.
- **E004**: 재생성 1회. 1차 출력이 예시(c3:m07 "서연 파트장님, …")를 따라 호칭 '파트장님'을 넣어 `fact_added`(person)로 걸렸고, 2차에서 뺐다(change_reasons: "원문에 없던 호칭 '파트장님'을 빼고"). B도 같은 이유로 재생성 1회(첫 실측과 같은 패턴). **검증 루프가 문체 예시의 과잉 모방을 막는 역할을 실제로 했다.** 결과는 B와 글자까지 같다.
- **E005**: recall 0.50 — 정답 c4:m06("다음 달에 밥 한번 먹자")이 든 묶음은 3위로 들어왔지만 모델은 다른 묶음만 근거로 들었다. 출력은 B에서 덧붙인 "시간 돼?"가 없어져 원문에 더 가깝다.

## 눈에 띈 것
- **A 기준선의 존댓말 전환**: E005 A "어떠세요?" — 첫 실측과 같은 패턴(상대 정보가 없으면 격식으로). E003 A는 이번엔 반말 유지. A는 변동이 크다.
- **E004 B/C 결과 동일, A와는 다름**: 동기 사례에서 "미안합니다 → 미안해요"는 설정(격식 3·친근함 4)이 결정했고 예시는 영향이 없었다. 파트장 발령 뒤 존댓말이 맞다는 `expected_notes`는 셋 모두 충족.
- **warnings 품질**: E002 B "'이번 주 금요일은'을 '금요일까지는'으로 읽고 고쳤습니다"처럼 모델이 자기 변경의 위험을 정확히 적는다. UI에 warnings를 보여 주자는 첫 실측 메모의 제안이 다시 확인됨.
- 지연 최대 14.5초(E004 C)는 재생성 포함 2회 호출 + 긴 출력(1,270 토큰). 요청 예산 20초 안이지만 재생성이 두 번이면 넘는다 → `MAX_REGENERATIONS=1` 유지가 맞다.

## 판단
- 5사례·1회로는 C가 B보다 낫다고 말할 수 없다. 다만 **"과거에 같은 장면에서 쓴 표현을 그대로 가져온다"(E002)와 "예시를 과하게 베끼면 검증이 막는다"(E004)** 두 기전이 실제 호출에서 확인됐다. 이게 2주차 C 경로의 완료 조건이다.
- 비교 판정은 사례 20개 이후 `--repeat 3`으로. 그때 C의 입력 토큰 증가(1.8배)에 견줄 품질 차이가 있는지 블라인드 평가로 본다.
- D는 3주차에 그래프 맥락을 붙인 뒤 측정한다. 지금 D는 C와 같다.
