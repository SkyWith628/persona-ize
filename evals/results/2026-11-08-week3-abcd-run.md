# 3주차 실측 메모 — A/B/C/D 첫 비교, Claude 실제 호출 (2026-11-08 밤)

`run_eval.py --provider anthropic --conditions A,B,C,D`, 사례 5개(E001~E005), `--repeat 1`, Opus 5.5 `LLM_EFFORT=medium`, 프롬프트 `rewrite-v1`.
C = 문체 예시 kNN(e5-small, pgvector). D = C + 그래프 사실 맥락(`GraphContextRetriever`, 로컬 Neo4j, haiku-4-5로 36 에피소드 수집 → 엔티티 15, 엣지 41).
요약 CSV: [eval-week3-abcd-anthropic.csv](eval-week3-abcd-anthropic.csv). 직전 A/B/C 실측: [2026-11-08-week2-abc-run.md](2026-11-08-week2-abc-run.md).

## 조건별 집계 (5사례씩)
| | A | B | C | D |
|---|---|---|---|---|
| recommended / fallback | 5 / 0 | 5 / 0 | **4 / 1** | 5 / 0 |
| 모델 호출 수 (재생성 포함) | 5 | 6 | 6 | 6 |
| 지연 중앙값 / 최대 | 4.0초 / 5.9초 | 3.7초 / 6.1초 | 4.7초 / 15.1초 | 4.7초 / 14.8초 |
| 입력 / 출력 토큰 (캐시 읽기 제외) | 1,224 / 1,643 | 1,823 / 1,616 | 2,843 / 2,414 | 5,058 / 2,578 |
| 검색 recall (relevant_msg_ids 있는 3사례: E002·E004·E005) | - | - | 1.00 / 1.00 / 0.50 | 1.00 / 1.00 / **1.00** |

D는 사실 문장 4개가 더 들어가 입력이 C의 1.8배(B의 2.8배)다. 지연은 C와 같다(검색 자체는 수십 ms, 비용은 토큰).

## D가 C와 달라진 곳
- **E005 (친구·일정 조율, `needs_graph` 성격)**: C는 정답 c4:m06·m07("다음 달에 밥 한번 먹자")을 반만 가져왔는데(0.50), D의 그래프 맥락 4개 중 하나가 바로 그 사실("사용자가 최유진과 다음 달(2026-11)에 밥을 먹자고 제안했다")이어서 recall 1.00. 출력은 C와 같고, 모델은 warnings에 "지난번 약속한 밥 약속이라면 직접 덧붙여 주세요"라고 적었다 — **맥락을 내용으로 끌어들이지 않는다**는 프롬프트 규칙을 지켰다. 흩어진 약속을 연결하는 D의 기전이 실제 호출에서 처음 확인된 사례.
- **E003 (동생·부탁)**: C는 **모델 거절**(`fallback_original`, 아래), D는 "토요일 오전에 차 좀 빌려줄 수 있어? ㅋㅋ". D의 맥락에 "2026-10-10 토요일 저녁 엄마 생신 모임" 사실이 있어 모델이 warnings에 "같은 토요일에 생신 모임이 있는데 어느 토요일인지 확인해 달라"고 적었다. 사실을 본문에 넣지 않고 경고로만 쓴 것은 의도대로다.
- **E001·E002·E004**: 결과 문장은 C와 같거나 어미만 다르다(E001 D '보내드리겠습니다' vs C '보내드릴게요'). 그래프 맥락이 어조를 바꾼 흔적은 없다.

## 그래프 맥락의 품질 문제 (다음 작업)
1. **다른 방의 사실이 섞인다.** 박지현 질의에 c4(친구) 홈커밍, 이서연 질의에 c2(동생) 케이크·c1 팀장 사과가 들어왔다. 상대 노드 중심 거리 재정렬은 약한 가중치라 범위를 좁히지 못한다 → 엣지의 양 끝이 **상대 노드이거나 상대와 연결된 Event 노드**인 것만 남기는 필터(또는 Cypher 1~2홉)로 바꾼다.
2. **"주간보고 초안 공유" 사실이 5사례 중 4곳에 나온다.** 질의와 무관한데 BM25·임베딩 모두에서 상위로 잡히는 듯. 1번 필터와 함께 사실 문장의 `name`(Relationship/Involved) 가중치를 본다.
3. **사용자 이름이 '사용자'로 들어갔다.** eval 사용자의 대화방은 `me_name` 열이 생기기 전에 만들어져 에피소드 본문이 "박지현 → 사용자"였다. 그래프에 '사용자'와 '김민수' 엔티티가 따로 섰다. 적재기가 빈 `me_name`을 채우도록 고쳤지만(이번 커밋) 이미 들어간 36개는 그대로다 → 다음 측정 전에 eval 그룹을 지우고 재수집(haiku 36회).
4. recall 계산은 그래프 사실의 출처 에피소드 이름을 쓴다. 그래프는 한 사실에 여러 출처가 붙으므로 C보다 유리한 지표다. D vs C는 recall보다 **블라인드 평가**로 봐야 한다.

## 눈에 띈 것
- **E003 C 모델 거절**: Opus가 "토요일 오전에 차 좀 빌려줄 수 있어?" + 동생 방 문체 예시(국밥·케이크·ㅋㅋ)에 `refusal`로 응답했다. 프로바이더가 이를 모델 장애(503 계열)로 번역해 재생성 없이 원문 유지. 사용자 입장에서는 "추천 실패"다. 거절은 장애가 아니라 **재생성 1회 대상**으로 다루고, 그래도 거절이면 원문 유지가 맞다 → 워크플로 과제.
- **B 조건 "돼?"** 재현(첫 실측과 같음): "토요일 오전에 차 좀 빌려줄 수 있어? 돼?" — `directness=5` 과잉. 문체 예시가 있으면(C·D) 사라진다.
- 재생성은 E004에서만 B·C·D 각 1회, 모두 1차 출력이 원문에 없는 호칭('서연 씨'/'파트장님')을 넣어 `fact_added`. 이번부터 `first_attempt_violations` 열에 그대로 남는다.
- 지연 최대 15초(E004 C·D)는 재생성 2회 호출 합계. 요청 예산 20초 안.
