# Persona_ize 관련 논문 검토 및 설계 적용 판단

검토일: 2026-10-28. 설계 대상: 한국어 관계별 페르소나 기반 메시지 첨삭.

## 1. 결론

**과거 표현을 검색해 개인화하는 방향은 참고할 근거가 있다. 다만 관계별 한국어 첨삭에서의 효과는 직접 검증해야 한다. GraphRAG를 필수로 채택할 근거는 부족하다.**

바로 반영할 것은 사실 맥락과 문체 예시의 구분, 설명 가능한 스타일 설정, 사용자 검토, 검색 없는 기준선, 사용자·시간 분리 평가다. 학습 기반 검색·스타일 전용 임베딩·GraphRAG·디코딩 제어는 추가 실험 대상으로 둔다.

이 문서는 논문 요약과 프로젝트 적용 판단을 구분한다. 논문을 재현하거나 모든 최신 연구를 망라한 체계적 문헌고찰은 아니다. 아래 ‘검토 깊이’는 원문 중 실제 확인 범위를 뜻하며, 부록과 코드 전체를 검증했다는 의미가 아니다.

## 3. 핵심 논문 분석

### P1. LaMP: When Large Language Models Meet Personalization

Salemi et al., ACL 2024. [논문](https://aclanthology.org/2024.acl-long.399/) · [원문](https://aclanthology.org/2024.acl-long.399.pdf)

- **질문·방법:** 사용자 과거 기록 일부를 검색해 입력에 붙이면 개인화가 개선되는가? 분류 3개·생성 4개 과제를 구성하고 BM25, 의미 검색, 최신 기록 선택 등을 비교한다. 사용자 분리와 시간 분리를 제공한다.
- **확인한 결과:** 개인화 효과는 과제와 설정에 따라 다르다. 특히 Table 4의 zero-shot 트윗 재작성에서는 개인화 후 ROUGE가 낮아지는 조건이 있다. ‘기록을 넣으면 항상 좋아진다’는 해석은 부정확하다.
- **한계:** 트윗 재작성도 한국어 상대별 메신저 첨삭과 다르며, ROUGE가 개인 문체나 사실 보존을 직접 판정하지 않는다.
- **적용 판단:** 검색 없는 기준선과 무작위·최신·키워드·의미 검색을 비교한다. 같은 사용자라는 이유만으로 이력을 무조건 넣지 않는다. 평가 정답과 미래 기록의 검색 유입을 막는다.

### P2. Optimization Methods for Personalizing Large Language Models through Retrieval Augmentation

Salemi, Kallumadi, Zamani, SIGIR 2024. [원문](https://arxiv.org/html/2404.05970v1)

- **질문·방법:** 의미적으로 비슷한 기록이 생성에 가장 유용한 기록인가? 최종 개인화 결과의 피드백을 사용해 검색기를 강화학습 또는 지식 증류로 최적화하고 검색기 선택도 연구한다.
- **확인한 결과:** LaMP 7개 데이터셋 중 6개에서 유의한 개선을 보고한다.
- **한계:** 학습 데이터와 목적 지표가 필요하다. 생성 지표를 잘못 고르면 검색기도 잘못된 방향으로 최적화된다. 한국어 관계별 첨삭 성능을 입증한 결과가 아니다.
- **적용 판단:** 초기에는 검색기를 학습하지 않고 검색 예시 ID와 최종 사용자 평가를 연결해 기록한다. 이후 충분한 동의 데이터가 쌓이면, 단순 유사도 대신 ‘말투 적합성과 사실 보존에 도움 되는 예시’를 고르는 재정렬을 실험한다.

### P3. Can You Make It Sound Like You? Post-Editing LLM-Generated Text for Personal Style

Baumler et al., ACL 2026. [논문](https://aclanthology.org/2026.acl-long.2030/) · [원문](https://aclanthology.org/2026.acl-long.2030.pdf)

- **질문·방법:** 사람이 LLM 초안을 수정하면 자기 문체를 되찾는가? 사전 등록된 온라인 연구에서 81명이 개인 스타일이 중요한 글을 수정했다.
- **확인한 결과:** 수정 후 자기 글과의 문체 유사성이 높아졌지만 LLM 문체의 흔적과 다양성 감소가 남았다. 사용자 체감 진정성과 임베딩 측정은 일치하지 않았다.
- **한계:** 비보조 기준 글이 제한적이고 통제·처치 과제가 달랐다. 실제 수신자에게 전송되는 상황이 아니며, 사용자 초안의 AI 첨삭과도 흐름이 다르다. 논문도 측정 신뢰성의 한계를 밝힌다.
- **적용 판단:** 직접 수정·원문 복귀·변경 비교를 제공한다. 스타일 점수를 제품 성공의 유일한 기준으로 쓰지 않는다. 사용자 만족과 문체 특징을 따로 측정한다. 이 논문은 ‘우리 RAG가 해결한다’는 증거가 아니라 해결할 문제가 존재한다는 근거다.

### P4. PersonaAgent with GraphRAG: Community-Aware Knowledge Graphs for Personalized LLM

Liang, Zhang, Guo, arXiv:2511.17467v1, 2025. [원문](https://arxiv.org/html/2511.17467v1)

- **방법·결과:** 개인 기록과 다른 사용자의 커뮤니티 기록을 결합한다. 뉴스 분류·영화 태깅·상품 평점의 세 과제이며, 활동 이력이 많은 사용자 100명씩을 선택한다. Table 1의 영화 F1은 0.424→0.662다. 초록의 56.1%는 약 0.238의 절대 차이에 대한 상대 개선이다.
- **한계·확인 사항:** 관계별 문체 생성과 신규·희소 사용자를 검증하지 않는다. 개요의 dense search 설명과 방법절의 TF-IDF cosine 정의 사이 차이가 있어 재현 전에 구현 확인이 필요하다. 우리 용도에는 개인 검색·커뮤니티 신호·그래프 자체의 기여를 분리한 실험이 더 필요하다.
- **판단:** 초기 필수 채택 근거로 부족하다. 다른 사용자의 대화를 가져오는 구조는 채택하지 않는다. 동일 사용자 범위의 사건 연결만 후속 비교한다.

### P5. From Local to Global: A Graph RAG Approach to Query-Focused Summarization

Edge et al., arXiv:2404.16130, 2024 초판 / 2025 v2. [논문](https://arxiv.org/abs/2404.16130)

- **질문·방법:** 대규모 문서 전체의 주제를 묻는 질문에 답하기 위해 개체 그래프와 커뮤니티 요약을 만들고 답변을 종합한다.
- **근거 범위:** 백만 토큰 규모 자료의 전역적 이해 질문에서 포괄성과 다양성 개선을 보고한다. 한 문장의 말투 변환과 다른 목표다.
- **적용 판단:** ‘지난달 이 상대와 무엇을 조율했는가’ 같은 회고·관계 요약에는 후보가 된다. 기본 첨삭에서는 초기 비용·요약에 의한 표현 손실을 감수할 이유를 먼저 검증한다. 그래프 요약만 스타일 예시로 쓰지 않고 원문 발화로 돌아갈 수 있게 한다.

### P6. LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory

Wu et al., ICLR 2025; arXiv 2024 초판, 2025 개정. [논문](https://arxiv.org/abs/2410.10813) · [검토 본문 v1](https://arxiv.org/html/2410.10813v1)

- **방법:** 정보 추출, 여러 세션 연결, 시간 추론, 지식 갱신, 답변 보류를 평가하는 500문항 벤치마크다. 색인·검색·읽기를 구분하고 대화 단위와 시간 조건을 연구한다.
- **확인한 사항:** 시간 범위 필터는 도움이 될 수 있지만 잘못 추출하면 필요한 기록을 제외한다. 검색 성공 후 생성이 실패하는 사례도 분석한다.
- **한계:** 장기 기억 기반 질의응답이며 문체 재현 과제가 아니다. 그 점수를 우리 서비스 품질 수치로 옮길 수 없다.
- **적용 판단:** 오래된 약속과 수정된 약속을 구분하고, 근거가 없으면 원문 밖 사실을 추가하지 않는다. 시간 조건은 명시적 단서가 있을 때만 적용한다. 검색·생성·최종 결과를 각각 평가한다. 현재 설정으로 바뀐 말투를 오래된 예시가 덮어쓰지 않는 테스트를 추가한다.

### P7. Interpreting Style Representations via Style-Eliciting Prompts

Kim, Jurgens, Findings ACL 2026. [논문](https://aclanthology.org/2026.findings-acl.2039/) · [원문](https://aclanthology.org/2026.findings-acl.2039.pdf)

Style representation (문체 표현): 문체 특징을 담는 벡터 또는 설명. 의미 검색용 벡터와 학습 목적이 다를 수 있다.

- **방법:** 26개 범주·1,010개 스타일 특징을 바탕으로 생성한 데이터를 이용해, 문체 표현에서 생성용 스타일 지시문을 복원하는 디코더를 학습한다.
- **확인한 결과:** 스타일 지시 복원과 문체 제어에서 직접 예시를 주는 기준선 대비 개선을 보고한다.
- **한계:** 논문의 학습 모델을 단순한 ‘LLM에게 말투 요약 요청’으로 대체하고 같은 성능을 기대할 수 없다. 한국어 존대·호칭·관계 제어는 별도 검증해야 한다.
- **적용 판단:** 사용자에게 ‘정중함 80점’만 제시하지 말고 호칭, 종결형, 직접성, 길이, 이모지 등 수정 가능한 설정을 제공한다. 자동 분석은 출처 예시를 붙인 설정 후보로만 제안한다. 논문 모델 자체의 도입은 후속 실험이다.

### P8. One Agent to Serve All: a Lite-Adaptive Stylized AI Assistant for Millions of Multi-Style Official Accounts

Fan et al., Findings ACL 2026. [논문](https://aclanthology.org/2026.findings-acl.698/) · [원문](https://aclanthology.org/2026.findings-acl.698.pdf)

- **방법:** WeStar는 사실 맥락과 스타일 자원을 구분하고 스타일 군집·파라미터 공유·스타일 강화 선호 최적화를 사용한다.
- **확인한 결과·한계:** 400개 질의 오류 분석은 맥락 검색과 스타일 검색 실패가 서로 다른 품질 축에 영향을 줌을 보여준다. 충분한 군집 데이터가 필요하며 산업용 비공개 데이터에 따른 재현 한계가 있다. 공식 계정 QA와 개인 메신저 첨삭도 다르다.
- **적용 판단:** 사실 맥락과 문체 예시의 입력 역할을 분리한다. 이는 논문의 파라미터 주입 구조를 그대로 재현하는 것이 아닌 설계 원칙의 차용이다. 사용자별 학습이나 군집 모델은 MVP에서 제외한다.

### P9. Drift: Decoding-time Personalized Alignments with Implicit User Preferences

Kim et al., Findings EMNLP 2025. [논문](https://aclanthology.org/2025.findings-emnlp.324/) · [원문](https://aclanthology.org/2025.findings-emnlp.324.pdf)

Decoding (디코딩): 모델이 다음 토큰을 선택하며 문장을 만드는 과정.

- **방법:** 사용자 선호를 설명 가능한 속성들의 조합으로 모델링하고, 속성별 보상 신호로 동결 모델의 토큰 선택을 제어한다. Perspective·PRISM에서 50~100개 예시를 이용한 결과를 보고한다.
- **한계:** 학습이 없다는 것이 실행 비용이나 모델 접근 제약이 없다는 뜻은 아니다. 토큰 확률·로짓 수준 제어를 일반 텍스트 생성 API가 제공한다고 가정할 수 없다. 일반 응답 선호와 상대별 말투도 다르다.
- **적용 판단:** 간결함·감정 표현·직접성 등 속성 모델은 참고한다. 초기에는 승인된 설정으로 표현하고, 디코딩 알고리즘은 자체 모델 서빙을 고려할 때 별도 평가한다. 단순 프롬프트 적용을 Drift 구현이라고 부르지 않는다.

### P10. Evaluating Text Style Transfer Evaluation: Are There Any Reliable Metrics?

Mukherjee et al., NAACL Student Research Workshop 2025. [논문](https://aclanthology.org/2025.naacl-srw.41/) · [원문](https://aclanthology.org/2025.naacl-srw.41.pdf)

- **방법:** 영어·힌디어·벵골어의 감정 전환과 유해 표현 완화에서 자동 지표와 사람 평가의 상관을 비교한다. 문체 변화·내용 보존·자연스러움을 구분하고 LLM 평가와 지표 조합도 연구한다.
- **한계:** 한국어와 관계별 존대 변환은 평가 범위 밖이다. 최적 지표를 정답을 보고 고르는 oracle 결과를 실제 운영 성능으로 볼 수 없다.
- **적용 판단:** 사실/의도 보존, 상대 적합성, 개인 스타일, 자연스러움을 별도 보고한다. 사람 평가로 자동 점수의 유효성을 확인하고, 특정 점수 개선만으로 출시를 결정하지 않는다.

### P11. BERTScore: Evaluating Text Generation with BERT

Zhang et al., ICLR 2020; arXiv 2019 초판. [논문](https://arxiv.org/abs/1904.09675)

- **방법·근거:** 문맥 임베딩으로 후보와 참조의 토큰 유사도를 계산한다. 번역·이미지 캡션 시스템과 적대적 의역 과제에서 평가한다.
- **프로젝트 해석:** 유사도 점수이지 원문 사실 전체의 논리적 동등성을 보증하는 검사기는 아니다. ‘내일까지 가능’과 ‘내일까지 불가능’의 구분, 기한·수량·약속은 별도 판정이 필요하다.
- **적용 판단:** 한국어에 적합한 인코더와 설정을 고정해 보조 지표로 사용한다. 숫자·부정·상대 시점에 대한 검증과 사람 검토를 병행한다. BERTScore가 높다는 이유로 사실 오류를 통과시키지 않는다.

## 5. 논문을 종합한 설계 보완안

아래는 논문의 직접 결론이 아닌 **이 프로젝트를 위한 설계 판단**이다.

### 5.1 검색 결과를 두 종류로 분리

```text
원문 + 최근 대화 + 상대별 현재 설정
                │
     ┌──────────┴──────────┐
     ▼                     ▼
사실 맥락 후보          문체 예시 후보
같은 상대·사건·시간      같은 상대의 본인 발화
출처와 시점 필수        요청 상황·표현 방식 중심
     └──────────┬──────────┘
                ▼
역할을 구분한 입력 → 첨삭 → 의미 검사 → 사용자 수정·적용
```

- 사실 맥락도 자동으로 현재 사실이 되지 않는다. 원문·현재 대화가 우선이며 충돌하면 묻거나 추가하지 않는다.
- 문체 예시에 등장한 사유·시간·금액은 현재 내용으로 복사하지 않는다.
- MVP는 같은 DB와 한 검색 모듈을 사용해도 된다. 역할 분리가 두 벡터 DB나 두 번의 LLM 호출을 필수로 뜻하지 않는다.
- 검색 결과마다 `purpose=context|style`, `source_message_ids`, `speaker_role`, `sent_at`, `contact_id`를 유지한다.

### 5.2 개인화 계층

사용자가 이번 요청에 명시한 조건 → 현재 상대별 설정 → 같은 상대의 승인된 예시 → 일반 표현 순으로 우선한다. 다른 상대·다른 사용자의 예시는 기본 경로에서 제외한다. 이 계층은 제품 가정으로 실험해야 한다.

### 5.3 검색의 비교 실험

A 일반 첨삭, B 페르소나만, C B+과거 예시, D C+그래프를 유지한다. C 안에서도 최신·무작위·키워드·의미 검색을 비교한다. 관계별 필터 자체와 검색 방식의 효과를 구분한다.

초기 실험은 순차 진행한다. 20~30개 개발 사례로 명백한 오류를 제거하고 설정을 고정한 후, 기존 120개 평가 사례를 사용한다. 동일한 토큰 예산·모델·예시 수 조건을 맞춘다. 그래프 비교는 그래프 없는 경우와 개인 기록 범위를 같게 해 비교한다.

### 5.4 실패 기준을 먼저 고정

문체 점수가 높아도 날짜·수량·가능 여부·약속·거절 의도가 바뀌면 실패다. 자동 탐지의 미탐·오탐도 평가한다. 규칙 통과는 의미 보존의 보장이 아니다.

평가표는 내용 보존 / 상대 적합성 / 개인 문체 / 자연스러움 / 수정 부담을 분리한다. 후보 순서와 시스템 이름을 가리고 본인 선호를 평가하며, 사실 보존은 별도 평가자가 확인할 수 있다.

합성 데이터는 기능·오류 테스트에 사용한다. 개인 문체 재현의 실증에는 동의받은 실제 본인 작성 예시와 해당 사용자의 평가가 필요하다. 한 사용자의 반복 사례를 독립 사용자 표본으로 계산하지 않고 사용자 단위 집계·불확실성을 보고한다.

## 7. 검증 상태와 남은 작업

- 논문 링크·제목·발표 정보와 명시한 범위의 원문을 확인했다. 발표자료 인용은 관련성에 따라 재분류했다.

- LaMP는 과제별 데이터 이용 조건이 다르므로 공개 벤치마크라고 상용 학습에 바로 재사용하지 않는다. 본문 Appendix F를 출발점으로 실제 배포 데이터의 조건을 별도 확인한다.
- 관계·상황 조합의 한국어 평가셋과 사용자 연구는 앞으로 구성해야 한다. 현재 문서로 제품 효과가 입증된 것은 아니다.
