## C. 뒤로 미룬 것 (근거가 생기면)

- React UI(`apps/web`) — 포트폴리오 정리 단계에서. 지금 화면으로 시연 가능.
- 그래프 스파이크 분산 측정 2~3회 — 로컬 Neo4j·haiku라 비용은 작지만 지금 결정에 영향 없음.
- D 조건 커뮤니티 요약·재정렬(Graphiti build_communities) — 설계서가 "시간 부족 시 가장 먼저 줄일 것"으로 지정.
- Sonnet 5.5 vs Opus 5.5 본격 비교 — 사례 20개는 11/24에 채웠다. 평가 마무리(A15, 예전 B1)와 함께.
- 설치형 PC 프로그램(트레이 상주 + 전역 단축키 + 팝오버, 와이어프레임 P1·P2) — 이 PC에 node가 없어 만들지 않았다. 서버 쪽은 Bearer 토큰(`POST /v1/auth/token`)과 `channel: "desktop"`이 준비돼 있다.
- 아이폰 앱 정리(11/12 검토): 로그인을 쿠키+CSRF에서 `POST /v1/auth/token`(Bearer)으로, 조건이 `D`로 고정. 시연 프로토타입은 상대를 고르면 바로 첨삭하던 동작이 PC 모드에서도 "고르기만"으로 바뀌었다 — 시연 전에 되살릴지 정한다.
- 시연 프로토타입(11/14 PC 확인에서 남은 것): VoiceOver·실제 한글 키보드(`R` 단축키가 한글 입력 상태에서 먹히는지 포함), Mac 단축키, 실제 오류·원문 유지 응답은 보지 않았다. 원문 유지 화면에서 `Enter`가 다시 만들기(재호출)인 점, 로딩 중 입력하면 이미 비용이 나간 응답을 버리는 점은 시연 전에 정한다. PC 입력칸에 `aria-label`·결과 알림 영역(`aria-live`)이 없고, 결과 창이 메신저 창과 겹친다.
- 가져오기 임베딩(11/13에 응답 뒤로 옮김)의 남은 것: 임베딩은 여전히 서버 프로세스 안에서 CPU를 쓴다 — 별도 작업 프로세스·대기열은 없다. 큰 가져오기 직후 그 방의 C/D 첨삭은 묶음이 끝날 때까지 예전 묶음으로 돈다. 진행률(11/14)은 서버 메모리에만 있어 재시작 직후에는 수치 없이 보인다(화면은 11/14에 확인: 묶음 1,500개가 약 20초).
- 무중단 배포(지금은 backend 교체 중 10~20초 동안 프록시가 "점검 중"으로 답한다), 서버 밖 백업 복사, 모니터링·알림.
- 세션 목록에 기기 종류 표시(`sessions.client` 열), 내보내기 스트리밍, 그래프 삭제 실패의 재시도 기록, scrypt 비용 인자 상향.
- 소셜 로그인·이메일(비밀번호 자가 재설정) — 지금은 운영자가 `scripts/reset_password.py`로 재설정한다.
- 검토에서 남은 한계(2026-11-11): 0009 이전에 그래프에 수집된 상대는 `contacts.graph_name`이 비어 있다(이름을 이미 바꾼 상대는 `graph_reset.py`나 직접 채우기. 경칭·공백만 다른 경우는 11/24부터 `scripts/graph_names.py`로 맞춘다). 첨삭 요청은 연결이 끊겨도 끝까지 돌아 토큰이 기록된다(11/25 실측). 토큰이 빠지는 것은 요청 태스크가 강제로 취소될 때뿐이다(서버 종료의 강제 취소 등, 지금 운영 설정에서는 드물다) — 고친 코드는 넣지 않고 남겨 두었다(`decisions.md` 11-25, 스트리밍·요청 시간 제한·`--timeout-graceful-shutdown`을 넣을 때 되살린다). 예산이 나중에 생겨 더 오래된 메시지를 넣으면 수집 순서가 뒤바뀐다(Graphiti의 처리 미확인). 잠금·한도 집계는 프로세스 하나 기준.
- 그래프 수집에서 보류된 메시지의 남은 것: 보류 건수는 대화방 통계와 관리자 대시보드에 보이고, 관리자 화면의 "다시 시도"로 푼다(11/14 전체 한 번에, 11/25부터 보류 표에서 대화방별로도 — API는 사용자별도 받는다). 어느 대화방에 몇 건이 보류됐는지는 관리자 화면의 보류 표(`GET /v1/admin/graph/held`)에 보이지만, 그 방의 **어느 메시지**인지는 여전히 서버 로그(`graph ingest gave up episode=…`)에만 있다(관리자 응답에 문장을 싣지 않는다). 화면에는 사용자 단위 버튼이 없고, 보류 표는 최근 50개 방까지만 보인다(쪽 넘김 없음). 다시 시도는 브라우저(모델 키를 뺀 서버)와 실제 모델(보류 2건이 풀려 그래프에 들어감) 둘 다에서 확인했다(11/14). 보류 표와 줄의 다시 시도는 브라우저로 폭 1400~390px, 그래프 꺼진 서버, 403·409 안내, 빈 목록까지 봤다(11/25, 가짜 그래프 저장소 — 좁은 화면에서는 표를 옆으로 밀어야 버튼이 나온다). 일시 장애로 보는 예외 목록(`is_transient`)과 3번 뒤 보류는 실제 모델 실패에서 확인하지 못했다(11/14 실제 수집 36건에서 실패가 나지 않았다).
- 화자 역할 고치기(11/14 방 전체 맞바꾸기, 11/15 화자별 지정·제외 — 원래 화자 이름 저장 0011)의 남은 것: 제외와 다시 올려 되살리기는 실제 그래프로 확인했다(11/15, 그 화자의 에피소드만 지우고 다시 넣는다). 화자의 역할만 바꾸는 경우(나↔상대, 내 이름이 바뀌어 방 전체를 다시 넣는 경우 포함)는 실제 그래프로 보지 않았다. 예전에 가져온 방은 같은 내보내기를 다시 올려야 이름이 채워진다(자동으로 채울 방법은 없다 — 원문에만 이름이 있다). 다시 올릴 때 이미 있는 화자의 역할은 지정을 달리해도 바뀌지 않는다 — 화면이 저장된 역할을 미리 골라 두고 다르게 고르면 알린다(11/15). 서버도 원문 가져오기(`imports/raw`) 응답의 `ignored_speaker_roles`로 따르지 않은 지정(이름·요청한 역할·저장된 역할·메시지 수)을 알리고 결과 화면이 보여 준다(11/25, 하나면 한 문단·둘 이상이면 머리말과 화자마다 한 줄인 목록(5명까지, 넘으면 '외 N건')·해법 한 줄. 새 메시지가 0건이면 대화방 삭제 대신 '화자별로 고치기'만 안내한다) — 역할은 여전히 바꾸지 않는다. 남은 것: 메시지 배열 가져오기(`imports`)의 `speaker_map`은 알리지 않고, 이름 없이 저장된 메시지는 그 업로드가 이름을 채운 다음 번부터 알리며, 아이폰 앱은 이 필드를 아직 읽지 않는다. 제외했던 화자를 되살리려면 파일을 다시 올려야 한다(대화방의 '이어서 가져오기'가 그 대화방을 골라 둔 채 가져오기로 보낸다 — 누구를 제외했었는지는 서버에 남지 않아 화면이 알려 주지 못한다). 한 대화방에 상대 쪽 화자가 여럿이어도 문체 묶음·그래프에서는 모두 그 대화방의 상대 한 사람으로 적힌다. 가져오기 결과 화면에는 버튼이 없다(대화방 화면에만). 역할 고치기 작업은 `imported=0`·`duplicates=0`인 `import_jobs` 행이다 — 관리자 작업 목록이 종류(`kind`)로 갈라 보여 준다(11/25, `import_job_kind`). 가져오기 건수를 세는 집계는 아직 없다(그래프 작업 수는 역할 고치기도 센다 — 그래프를 다시 넣으므로). 최근 작업 목록의 줄 수 제한(50)은 두 종류가 함께 쓴다.
- 그래프 에피소드 삭제(11/14에 모델 호출 없이 지우도록 바꿈)의 남은 것: 남는 개체의 요약을 비운다 — 다음 수집 때 graphiti가 다시 채우지만, 수집이 더 없으면 빈 채로 남는다(지금 앱은 요약을 읽지 않는다. 커뮤니티 요약(D 재정렬)을 쓰게 되면 다시 본다). 개체의 `attributes`에 지운 대화에서 나온 값이 남을 수 있는 것은 예전과 같다. 큰 대화방(수천 건)에서의 삭제 시간은 재지 않았다.
- 종료 대기 제한(11/14)의 남은 것: 실제 haiku 수집 중의 종료는 확인했다(넣던 에피소드까지 끝내고 6.7초에 내려감). 제한 시간(15초)을 넘겨 끊기는 경우는 테스트로만 봤다 — 그렇게 끊긴 에피소드는 그래프에 반쯤 들어갔을 수 있고, 다음 시작 때 같은 이름으로 다시 들어간다(예전의 강제 종료와 같다). 주기 정리(`housekeeping`)가 돌리는 이어받기는 종료 때 바로 끊는다.
- 가림 패턴 보강(이름·주소는 못 가린다).
- 검증 규칙의 남은 한계(11/24): 약속이 '알겠습니다'로 바뀐 경우, 일반 부정만 사라진 경우('아직 안 봤습니다' → '봤습니다'), 직함 없는 이름, 한 자리 수, 줄임말 요일('수욜')은 규칙으로 못 잡는다(`evals/preserve_rules.md`). 모델 보조 검증을 넣을지는 수치를 보고 정한다 — 재측정(예전 A12)은 11/24에 끝났고(dev 16사례 192회 중 190회 추천, `evals/results/2026-11-24-dev16-repeat3.md`), 넣을지는 아직 정하지 않았다. 구체안은 `docs/design/ml-judge-design-2026-11-25.md`.
