## 1. 완성의 정의 (제안)

아래 여섯이 모두 참이면 완성으로 본다. 설계서(`design/project-design.md` §3·§8·§11)의 지표를 그대로 가져왔고, 목표값은 실측 전 초기 합의 값이다.

1. **시연이 처음부터 끝까지 돈다** — `guides/demo-script.md`의 10분 흐름(장면 1~5)이 시연 장비에서 두 번 연속 문제없이 끝난다.
2. **비교표가 사람 점수까지 채워졌다** — A/B/C/D × 사례(D2의 수) × 3회, 열: 사실 보존, 스타일 블라인드 5점, C 대 A 선호, Recall@5, 지연 p95, 비용.
3. **D 조건의 채택·보류가 판정됐다** — 조건 4가지(흩어진 사건 연결, 시간·갱신, 맥락 오염, 비용·지연)마다 근거 사례와 함께.
4. **운영 서버가 `main`과 같다** — 재배포가 끝났고 스모크가 통과한다.
5. **제출물이 있다** — 최종 비교 보고서, 발표 자료, 포폴 README.
6. **공개 전 필수 항목이 닫혔다** — `/privacy`·`/terms`의 "확인 필요"가 0개.

| 지표 | 목표 | 지금 (11/25) |
|---|---|---|
| 핵심 사실 보존 | 98% 이상 | 규칙 통과 190/192 (dev 16사례) |
| 스타일 블라인드 5점 | 평균 4 이상 | 채점 안 함 |
| C가 A보다 선호 | 60% 이상 | 미측정 |
| Recall@5 | 0.8 이상 | C 0.90 / D 0.92 |
| 지연 p95 | 8초 | A 5.8 / B 4.6 / C 6.2 / **D 11.5초** (11/24 dev 16사례, `evals/summarize.py`) |
| 사례 수 | 120 (D2에서 60 제안) | 20 |

## 5. 에이전트로 이어서 일하는 방법

여러 날에 걸쳐 여러 세션이 일해도 어긋나지 않게 하는 규칙이다. 11/25 하루 동안 이 방식으로 PR 넷(22·25·26·28)을 넣었다.

- **단위**: 항목 하나(또는 서로 독립인 둘~셋)가 PR 하나. 브랜치는 최신 `main`에서 새로 딴다.
- **시작할 때**: `backlog.md`와 이 문서를 읽고, 그 사이 `main`에 들어온 것을 본다. 다른 세션(ML)이 쓰는 브랜치와 파일은 건드리지 않는다.
- **재현부터**: 백로그의 설명을 믿고 바로 고치지 않는다. 11/25에 두 번은 실제 문제가 설명보다 작았고(가져오기 건수 집계, 취소된 첨삭의 토큰), 한 번은 더 컸다(긴 화자 이름).
- **검증 게이트**: `ruff` → `pytest`(DB 없이 + 임시 Postgres) → 화면 테스트 → 화면을 고쳤으면 헤드리스 크롬으로 폭 둘 이상. 에이전트가 나눠 일하면 조율하는 세션이 변경을 읽고 합친 상태에서 전부 다시 돌린다.
- **비용 게이트**: 실제 모델 호출은 D3의 예산 안에서, 실행 전에 예상 호출 수와 비용을 적는다. 클라우드 세션은 키 없이 fake 프로바이더로만.
- **병합 게이트**: 초안 PR → CI 통과 → **사람이 요청할 때만** 병합. 핵심 경로(`ai/workflow.py`, `services/rewrite_service.py`, 검증 규칙)를 바꾸는 PR은 실제 모델로 몇 번 돌려 본 뒤에.
- **끝낼 때**: 끝낸 줄은 `backlog.md`에서 지우고 `decisions.md`에 5줄 이내로 남긴다. 확인하지 못한 것은 PR 본문과 `decisions.md`에 그대로 적는다.
- **넘겨줄 때**: 사람·팀원 차례가 된 항목은 준비물(체크리스트, 명령, 양식)을 만들어 두고 이 문서의 표에서 실행 칸을 따라 넘긴다.

**클라우드 세션이 지금 바로 시작할 수 있는 것**(결정·키·사람을 기다리지 않는다): T6-3 초안. (T1-1, T1-2, T2-1, T1-4의 틀, T2-3의 코드는 11/25에 끝났다.)
