# 와이어프레임 검토 (2026-11-10)

대상: `페르소나 키보드 앱 와이어프레임.pdf`(모바일 18화면 + 아이콘), `페르소나 키보드 앱 와이어프레임 (1).pdf`(웹·크롬 확장 15화면, 어드민 1화면).
사용 환경: 모바일은 카카오톡·텔레그램 위 키보드, PC는 사내 자체 메신저(설치형)에서 전역 단축키.
수정안 화면: [wireframes-v2.html](wireframes-v2.html) — 바뀌는 화면 9개(M1~M6, P1~P2, A1).

## 총평
흐름(대화 올리기 → 분석 리포트 → 키보드에서 한 번에)과 문구 톤은 좋다. 가장 큰 문제는 세 가지다. ① 키보드 호출 버튼의 위치가 플랫폼에서 불가능하다. ② PC가 크롬 확장이라 사내 메신저에서 못 쓴다. ③ "사실은 그대로"라는 서비스의 약속을 보여 주는 화면이 없다.

## 플랫폼 제약 (확인한 것 / 확인 필요)

**iOS 키보드**
- 키보드는 입력 대상에 직접 접근하지 못하고 `textDocumentProxy`로만 글자를 읽고 넣는다. 채팅 앱의 다른 화면(받은 메시지, 상대 이름)은 볼 수 없다. → 상대 자동 인식 불가, "최근 맥락(B 조건)"도 키보드에서는 얻지 못한다. 최근 메시지를 쓰려면 사용자가 복사한 내용을 받는 방식이 필요하다.
- 네트워크는 '전체 접근 허용'을 켜야 한다(기본은 꺼짐). 원본 18쪽의 안내 화면은 그대로 쓴다.
- 비밀번호 칸에서는 시스템 키보드로 바뀐다.
- **확인 필요**: 커서 앞 글자를 읽는 `documentContextBeforeInput`이 긴 글에서 일부만 돌려준다는 개발자 보고가 있다(공식 답변은 찾지 못함). 긴 초안이 잘릴 수 있으니 1주차에 실기기로 확인하고, 잘리면 "복사한 글로 만들기"를 대안으로 둔다.
- 한글 자판 전체를 새로 만드는 것은 큰 작업이다(자동완성·오타 교정). 시연용은 **자판 없이 첨삭 패널만 있는 보조 키보드**(지구본 키로 전환)로 범위를 줄이는 것을 권한다. M3이 그 형태다.

**Android**: 입력기(IME)로 같은 구조. 입력창 전체 글자를 읽을 수 있어 iOS보다 제약이 작다. 세부는 구현 전 공식 문서로 확인.

**텔레그램**: 대화 내보내기는 PC용 Telegram Desktop에서만 된다(JSON/HTML). 모바일 앱에는 없다. → 모바일 안내에 "PC에서 만든 파일" 명시.

**카카오톡**: 모바일 내보내기는 .txt. PC판은 자료마다 .txt/.csv로 엇갈리고 실행 환경에 따라 txt 구조도 다르다. → 실제 파일 샘플을 모아 파서를 맞춘다(백로그 C "카카오톡 내보내기 어댑터").

**PC 설치형 프로그램 (구현 전 검증 필요, 문서 확인 안 함)**
- 초안 가져오기: 입력칸 전체 선택 → 복사 → 클립보드 복원이 메신저 종류와 무관하게 통하는 방식이다. 접근성 API로 직접 읽는 방식은 메신저마다 지원이 다르다.
- macOS는 손쉬운 사용 권한이 필요하다. 회사 PC는 보안 프로그램(DLP·백신)이 키 입력 가로채기나 외부 전송을 막을 수 있다.
- **사내 대화가 외부 API로 나간다.** 회사 보안 정책상 금지일 수 있으니 온보딩 첫 화면에서 알리고, 허용 프로그램 목록·비밀번호 칸 차단을 기본으로 둔다.

## 프로젝트 원칙과 부딪히는 곳
- "합성 데이터만 외부 서비스에 보낸다"(프로젝트 원칙) ↔ 와이어프레임은 실제 카카오톡 대화를 올린다. 공모전 시연은 합성 데이터로 하고, 실사용 전환은 동의·보관 정책을 정한 뒤로 둔다.
- "자동 전송 없음" — 모바일·PC 모두 '입력창에 넣기'까지만 하도록 문구를 명시했다(M3·P1).

## 시각 위계·일관성·접근성
- 위계: 결과 패널에서 추천 문장 → 보존 표시 → 주의 → 넣기 버튼 순으로 읽히게 했다. 원본은 조정 버튼 3개가 주 버튼과 같은 무게였다.
- 일관성: 웹메일 화면의 주 버튼이 검정(8쪽)과 파랑(12쪽)으로 섞여 있다 → 주 행동은 파랑 하나로. 상대 아이콘도 모바일은 관계 아이콘, 웹은 성 한 글자로 다르다 → 하나로 통일.
- 접근성: 키보드 패널의 칩·목록은 최소 44pt 높이를 지킨다(11쪽 목록 하단이 잘려 보인다). 회색 보조 문구(11~12px)는 대비 4.5:1 이상으로. 색만으로 상태를 구분하지 않게 ✓·문구를 함께 쓴다.

## 잘된 점
- 첫 화면의 "같은 메시지, 다른 답장" 예시가 가치를 2초 안에 전달한다.
- '나/상대' 화자 지정(6쪽)은 백엔드 `speaker_map`과 정확히 맞는다.
- 인터넷 오류·전체 접근 꺼짐 화면에서 "초안은 그대로 남아 있어요"를 알려 준다.
- 'AI 추정' 표시와 직접 고치기 경로가 있다.

## 우선순위
1. **PC를 설치형 프로그램으로 바꾼다** — 밝힌 사용 환경에서 크롬 확장은 동작하지 않는다.
2. **결과 화면에 보존 항목·주의·원문 유지를 넣는다** — 서비스의 차별점이고 백엔드에 이미 있다(`preserved_items`, `warnings`, `fallback_original`).
3. **저장·삭제 문구를 실제 동작에 맞춘다** — 틀린 개인정보 문구는 신뢰와 법적 위험이다.
4. 키보드 버튼 위치, 분석 두 단계, 페르소나 항목 통일.
