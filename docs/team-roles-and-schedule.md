## 역할

아키텍처 다이어그램(v2)의 블록 기준으로 나눈다. **비전공자와 팀장의 접점은 "파일 + PR"** 로 정한다: 비전공자가 표·마크다운·CSV를 채워 PR을 올리면 팀장이 리뷰하고 코드에 연결한다.

| 담당 | 아키텍처 블록 | 넘기는 산출물 (접점 파일) |
|---|---|---|
| 팀장·개발 | ② 파싱·중복 제거·C 경로(묶음+임베딩) / D 경로 Graphiti 연동 / ③ 워크플로(검색→프롬프트→첨삭→검증→재생성→원문 유지) / ⑤ 실험 하니스 | 코드, 프롬프트 파일 반영, 실험 결과 CSV |
| 사용자·시나리오 (아이디어 1) | ① 페르소나 속성(격식·친근함·길이·이모지·금지 표현)과 우선순위 규칙 / 입력 화면(상대 선택, 초안, 상황) / 사용자 인터뷰 | `persona_attributes.md`, 화면 와이어프레임, 합성 과거 대화(상대별 말투가 드러나는 것) |

**기능별 합의 지점** (함께 정해야 하는 것)
- 보존 항목 분류표: 평가 담당이 초안을 쓰고, 사용자·시나리오 담당이 현실성을 검토한다.
- 합성 대화: 사용자·시나리오 담당이 작성하고, 그래프 담당이 "사건 연결이 필요한 장면"(여러 방에 흩어진 일정·약속)을 요청해 넣는다. 평가셋과 그래프 점검이 같은 데이터를 쓰게 한다.
- D 채택 조건(다이어그램 ⑤): "흩어진 사건 연결 사례에서 C 대비 개선"을 판정하려면 그래프 담당이 그런 사례를 별도로 표시해야 한다.

**팀장의 부담 줄이기**
- 개발 우선순위: ③ 수직 기능 → C 경로 → 검증 → D 경로 → 재정렬. Community 요약(D 배치)과 재정렬은 시간이 부족하면 가장 먼저 줄인다.
- 비전공자 3명은 서로의 산출물로 일하므로 팀장 대기가 생기지 않는다: 시나리오 담당의 대화가 그래프 수집과 평가셋 입력이 되고, 평가 담당의 규칙이 검증기가 된다.
- 팀장이 코드로 옮기기 전에 파일 양식(열 이름)을 1주차에 확정한다.

공통: 합성 대화 작성, 주 1회 논문 스터디(1인 1편 발표, `literature-review.md` 15편 활용), 프롬프트 문서 검토.
프롬프트는 `backend/prompts/*.md`로 분리해 비전공자가 문서처럼 직접 수정할 수 있게 한다.

## 협업 도구: GitHub + Docker (전원 사용)

**목표: 비전공자도 코드를 만질 수 있되, 명령어 암기 없이 가능한 범위로 제한한다.**

### GitHub
- 하나의 저장소에서 전원이 일한다. `main`은 직접 수정 금지, 모든 변경은 **브랜치 → Pull Request(PR) → 팀장 리뷰 → 병합**.
- 비전공자는 **GitHub Desktop(마우스 UI)** 를 쓴다. 터미널 명령은 요구하지 않는다. 단순 문서·CSV 수정은 GitHub 웹에서 바로 편집해도 된다.
- 브랜치 이름: `역할/내용` (예: `eval/cases-week1`, `graph/schema-v1`).
- **폴더 소유로 충돌을 피한다.** 각자 자기 폴더 위주로만 수정한다.

| 폴더 | 주 담당 | 다른 사람이 수정할 때 |
|---|---|---|
| `backend/`, `docker/` | 팀장 | PR 필수 |
| `backend/prompts/` | 시나리오(첨삭 문구), 평가(검증 문구) | 팀장이 코드 연결 확인 |
| `evals/` | 평가 | |
| `data/synthetic/` | 시나리오 | 그래프 담당이 요청사항 추가 |
| `graph/` | 지식그래프 | |
| `docs/` | 전원 | |

- 비밀정보는 저장소에 올리지 않는다(`.env`는 `.gitignore`). API 키는 팀 공용 한도 키를 비밀번호 관리자로 공유한다.

### Docker
- `docker compose up` 한 번으로 **PostgreSQL(pgvector), Neo4j, 백엔드**가 같은 환경으로 뜬다. "내 컴퓨터에서만 된다" 문제를 없애는 용도다.
- Neo4j는 Aura 대신 **로컬 컨테이너**로 쓴다. 그래프 담당이 Neo4j Browser(`localhost`)에서 그래프를 바로 볼 수 있고 비용이 들지 않는다.
- 자주 쓰는 명령은 `Makefile`(또는 스크립트)로 감싼다: `make up`, `make test`, `make eval`. 팀원은 이 이름만 알면 된다.
- Docker Desktop은 메모리를 많이 쓴다. 팀원 노트북 사양(RAM)을 1주차에 확인한다.

### 비전공자가 직접 하는 코드성 작업 (범위)
- 프롬프트 `.md` 수정, 평가 CSV 편집, 합성 대화 JSON 편집
- `make eval`로 평가 실행 후 결과 CSV 확인
- Neo4j Browser에서 팀장이 준 Cypher 쿼리 실행과 수정
- 파이썬 코드 작성은 필수가 아니다. 원하는 사람은 팀장 리뷰를 거쳐 평가 스크립트 같은 작은 도구부터 한다.
