# Persona_ize 아이폰 화면 설계

첫 구현은 기존 웹 시연의 모바일 모드를 iPhone Safari에서 한 손으로 조작할 수 있게 다듬는다. 합성 대화로 초안을 작성하고 상대별 추천을 확인해 입력창에 넣는 흐름이 목표다. 실제 메신저 위에 뜨는 iOS 앱과 보조 키보드 확장은 `apps/ios/`에 첫 구현이 있다(빌드·시뮬레이터 실행까지 확인, 실기기 검증은 아래 4번).

## 화면 흐름

| 화면 | 위에서 아래로 읽는 순서 | 동작 |
|---|---|---|
| 상대 관리 | 최근 상대 → 전체 상대 → 대화 가져오기 | 합성 대화를 고르고 나/상대 화자를 지정한다. 상대 상세에서 격식·친근함·직설을 5단계로 편집한다. |
| 작성 | 상대 이름 → 합성 대화 → 초안 입력창 → 첨삭 도구 줄 | 도구 줄에 현재 상대를 표시한다. 누르면 최근 상대 3명과 전체 목록이 열린다. 빈 초안은 첨삭 버튼을 비활성화한다. |
| 추천 | 추천 문장 → 보존한 항목 → 주의 → 입력창에 넣기 | 응답의 result_text, preserved_items, warnings를 표시한다. 적용하면 작성 화면에 돌아간다. 닫으면 초안을 유지한다. |
| 원문 유지 | 원문 → 유지 사유 → 작성으로 돌아가기 | fallback_original이면 편집 중인 초안을 그대로 둔다. 통신 실패는 별도 상태로 표시하고 다시 시도할 수 있게 한다. |

합성 예시로 “내일 3시에 초안 보낼게”를 팀장에게 보낼 때 추천은 “내일 3시에 초안 보내겠습니다.”가 될 수 있다. 보존 항목은 서버가 반환한 값만 표시한다.

## 배치와 상태

작성 화면은 한 열로 구성한다. 화면 위에 상대 이름, 가운데에 스크롤 가능한 대화, 아래에 입력창과 도구 줄을 배치한다. 추천을 열면 입력 포커스를 해제하고 도구 줄 자리에 결과 패널을 펼친다. 긴 결과는 패널 내부에서 스크롤하고 적용 버튼은 하단 안전 영역 위에 둔다. 버튼 터치 영역은 최소 44 × 44pt에 대응하도록 설계한다.

POST /v1/rewrites 요청 시 상대와 초안을 기록한다. 응답 전에 어느 하나라도 바뀌면 이전 추천을 적용할 수 없게 한다. 같은 요청을 재시도할 때는 기존 Idempotency-Key를 사용한다. 화면은 요청 중 중복 탭을 막고 서버가 돌려준 상태를 기준으로 추천과 원문 유지를 나눈다.

## 구현 순서와 완료 기준

1. 기존 backend/app/web/proto.html, proto.css, proto.js의 모바일 모드에서 작성·추천·원문 유지 흐름을 구현한다. 실험 조건 선택은 접을 수 있는 시연 설정에 둔다.
2. 375·390·430px 너비에서 가로 스크롤, 긴 추천, 한글 입력 중 키보드 개폐, 화면 하단 버튼 접근을 확인한다. VoiceOver에서 상대 이름과 추천 상태가 읽혀야 한다.
3. 합성 초안으로 추천 적용, 닫기, 사실 보존 실패, 통신 실패 후 재시도, 대기 중 초안 변경을 각각 검증한다.
4. 네이티브(`apps/ios/`, 설치는 `apps/ios/README.md`)는 보조 키보드 전환, 전체 접근 권한 없이 앱 그룹의 준비 문장을 읽는지, 긴 초안 읽기·교체를 실기기에서 확인한다 — 아직 하지 않았다. 웹 시연은 화면 흐름과 서버 응답을 먼저 검증할 수 있지만 메신저 안에서의 입력 동작은 이 실험이 필요하다.
