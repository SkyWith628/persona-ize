# 코드 지도 (Floorplan)

`persona-ize-map.html`을 브라우저로 열면 프로젝트 코드를 눌러 가며 볼 수 있는 지도가 나옵니다. 인터넷 연결 없이 열립니다.

- 2026-11-25, `main` 기준으로 만들었습니다. 코드 파일 310개와 서버가 받는 요청 64개에 한글 이름과 한 줄 설명이 붙어 있습니다.
- 부분은 여덟 개입니다: PC 화면, 아이폰 앱, 요청을 받는 입구, 일을 처리하는 곳, 문장을 다루는 두뇌, 기록을 쌓는 곳, 도구와 실험, 자동 점검.
- 위쪽 **Start here**는 짧은 안내, **Flows**는 "메시지 한 건 고쳐 쓰기"와 "대화 가져오기"를 단계별로 보여 줍니다.
- 문서와 데이터 파일은 지도에 없습니다. 코드 파일만 그렸습니다.

## 믿어도 되는 정도

- 부분 나누기와 흐름은 사람이 코드 구조를 보고 정했습니다. 파일 사이의 선(import, 화면에서 서버로 가는 요청)은 도구가 코드에서 읽었습니다.
- 아이폰 앱에서 서버로 가는 선은 손으로 그은 한 줄입니다. 도구가 Swift 코드의 요청을 잇지 못했습니다.
- 파일별 설명은 AI가 파일 요약을 보고 썼고, 전부를 사람이 다시 읽어 확인하지는 않았습니다. 틀린 설명을 보면 `source/descriptions/`에서 고치면 됩니다.

## 다시 만드는 법

[haydenschmitty/floorplan](https://github.com/haydenschmitty/floorplan) 플러그인(MIT)으로 만들었습니다. Node.js 18 이상이 필요합니다.

1. `source/`의 `architecture.json`과 `descriptions/`를 저장소 루트의 `floorplan/` 폴더로 복사합니다. 이 폴더는 스스로 git에서 빠집니다.
2. Claude Code에서 "floorplan을 갱신해 줘"라고 하면 바뀐 파일만 다시 읽습니다.
3. 지도에서 Export로 내보낸 파일을 이 폴더의 `persona-ize-map.html`에 덮어쓰고, 고친 `source/`도 함께 올립니다.

내보낸 파일에는 건강 검진(Health) 결과를 넣지 않았습니다. 로그인 없이 열린 요청과 비밀값의 위치가 적히는 항목이라, 필요하면 받는 사람을 정해서 따로 내보냅니다.
